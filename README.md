# مَرسى | MARSA – منصة الإنذار المبكر والتنسيق البحري (MVP)

MVP يعمل فعليًا: يرصد المخاطر البحرية قبل ٤٨ ساعة، ويحدد السفن والموانئ المتأثرة، ويوصي لكل سفينة بالإجراء الأكثر أمانًا، ويوزّع السفن على الموانئ البديلة دون تجاوز ٨٨٪، ويرسل الإنذار المباشر بعد اعتماد ضابط الميناء، ويتابع رد السفينة، ويجهّز النشرات الملاحية ويوجّهها للجهات المختصة حتى صدورها رسميًا. كل البيانات **بيانات اختبار محاكاة**؛ لا يوجد اتصال فعلي بأي جهة، ومَرسى لا يبث تحذيرات NAVTEX/NAVAREA رسميًا.

## التشغيل محليًا
| الطريقة | الأمر |
|---|---|
| خادم (قاعدة بيانات SQLite دائمة، عدة أجهزة) | `npm start` ثم `http://localhost:8080` – Node.js 22.13+ بلا مكتبات خارجية |
| ملف واحد بلا خادم (حفظ في المتصفح) | `npm run build` ثم افتح `dist/marsa.html` |
| الاختبارات | `npm test` (١٨ اختبارًا: الرحلة الكاملة + Web Push) |
| إعدادات | انسخ `.env.example` إلى `.env` – لا مفاتيح حقيقية |

النسخة المنشورة: https://marsa-p8gz.onrender.com

## هيكل المشروع
```
shared/core.js        الجغرافيا، الممرات الملاحية، الموانئ، المحطات، خط الساحل والمياه الإقليمية
shared/service.js     منطق الأعمال: محرك المخاطر، التوصيات، توزيع الموانئ، الإنذارات، النشرات، السيناريوهات، السجل
server/server.js      REST API (/api/demo-login, /api/snapshot, /api/rpc/:method, /api/events, /api/push/*, /api/integrations/ncm/weather)
server/push.js        Web Push: VAPID (ES256) + aes128gcm، بلا مكتبات
web/sw.js             Service Worker (push, notificationclick) · web/manifest.webmanifest · web/icons/
server/store-sqlite.js + schema.sql   قاعدة البيانات SQLite (جدول لكل مجموعة بيانات)
web/app.js            الواجهتان (ضابط الميناء، جسر السفينة) · web/map.js خريطة تفاعلية (SVG، بلا خدمة خارجية)
test/scenario.test.js اختبارات الرحلة الكاملة
```
اخترنا الإبقاء على التقنية الحالية (JavaScript بلا اعتماديات + Node + SQLite) لأنها تعمل وموزعة على Render؛ منطق الأعمال مشترك بين الخادم والملف الواحد. الخريطة مرسومة محليًا لأن سياسة الأمان لا تسمح بخدمات خرائط خارجية؛ يمكن استبدالها بـ Leaflet + OpenStreetMap لاحقًا.

## الميزات المنفذة
- واجهتان مع تبديل فوري بلا تسجيل دخول: **ضابط الميناء** (يرصد، يتوقع، يقرر، يوزّع، الإنذار المباشر، النشرات، السيناريوهات، بيانات الاختبار، التكاملات، السجل) و**جسر السفينة** (هوية السفينة وموقعها، الإنذارات، التوصية، ETA وأثر الوقود، قبول/رفض بسبب/تأكيد، الإشعارات الملاحية، سجل الردود).
- محرك مخاطر قائم على قواعد قابلة للتعديل (رياح، أمواج، رؤية، تيارات، حالة الموانئ وازدحامها) لـ٤٨ ساعة؛ لكل خطر: الرقم، النوع، الموقع، البداية والنهاية، المستوى، السفن والموانئ المتأثرة، التفسير، الإجراءات الوقائية، ودرجة ثقة مُعلَنة كتقدير محاكى.
- توصية لكل سفينة من أربعة خيارات (الاستمرار، تغيير المسار، الانتظار/التأجيل، التحويل) بالأولوية: السلامة ثم الكفاءة ثم الزمن والوقود والتكلفة؛ لا مسار يعبر منطقة خطر مرتفع/حرج؛ عند غياب خيار آمن: انتظار + «تحتاج مراجعة الضابط». التوصيات مقترحة حتى يعتمدها الضابط، ويمكنه تعديلها.
- توزيع الموانئ البديلة عند الإغلاق أو الازدحام مع حساب الإشغال قبل/بعد، وحد ٨٨٪، واعتماد/رفض/تعديل يدوي.
- الإنذار المباشر بخطوتين (مراجعة ثم اعتماد وإرسال)، وحالات: مسودة، بانتظار الاعتماد، معتمد، أُرسل، تم التسليم، تم التأكيد، رفضت التوصية، في الانتظار خارج المياه الإقليمية؛ وإرسال الإنذار المحجوز عند دخول السفينة.
- النشرات: محلي/ساحلي/NAVAREA مع تحديد الجهات تلقائيًا، ومسار: مسودة ← قيد المراجعة ← معتمدة ← أُحيلت للجهات ← تأكيد الاستلام ← صدرت رسميًا (لا يُسجل الإصدار إلا بتأكيد الجهة المخولة مع رقم مرجعي)، ومسودة تحذير إنجليزية منظمة قابلة للتعديل والنسخ، وأداة NAVTEX.
- خمسة سيناريوهات عرض بضغطة وزر إعادة ضبط؛ سجل عمليات متسلسل بـ SHA-256 مع الحالة السابقة والجديدة، وفلترة وتصدير CSV؛ بحث في الجداول؛ تخزين دائم.

## ما هو محاكى
بيانات الطقس والتوقعات، مواقع السفن (AIS)، حالة الموانئ، الإرسال إلى شاشة الجسر وVHF، إحالة النشرات للجهات (نقاط `proposed://`)، تأكيدات الجهات (تُسجل يدويًا)، المياه الإقليمية (١٢ ميلًا من خط ساحل مبسّط، قاعدة خاصة بمسار الإنذار المباشر فقط)، الأعماق والقيود الملاحية، تكاليف الوقود والتشغيل.

## تكاملات تحتاج وصولًا رسميًا
المركز الوطني للأرصاد (توقعات بحرية)، مزود AIS، أنظمة تشغيل الموانئ، محطات NAVTEX السعودية المعتمدة، منسق NAVAREA IX (كراتشي)، خطوط الأساس الرسمية للمياه الإقليمية، الخرائط الملاحية المعتمدة.

## دليل اختبار سريع
1. ضابط الميناء ← «سيناريوهات العرض» ← سيناريو ١ ← في «الإنذار المباشر» راجع توصيات السفن ← «اعتماد وإرسال للسفن».
2. «التبديل إلى جسر السفينة» ← سفينة مستهدفة داخل المياه الإقليمية ← قبول أو رفض بسبب ← يظهر الرد عند الضابط.
3. سيناريو ٤ ← «محاكاة دخول المياه الإقليمية» ← يتحول الإنذار من «في الانتظار» إلى «أُرسل».
4. سيناريو ٢ أو ٣ ← «يوزّع» ← اعتماد/رفض/تعديل تحويل ← الإشغال لا يتجاوز ٨٨٪.
5. سيناريو ٥ ← اعتماد النشرة ← تسجيل الإحالة ← تسجيل استلام كل جهة ← تسجيل الإصدار الرسمي برقم مرجعي.
6. «سجل العمليات» ← فلترة وتصدير CSV ← التحقق من سلامة السجل. ثم «إعادة ضبط العرض».


## v5 – مركز العمليات وإشعارات الجوال الحقيقية

### ما الجديد
- **إشعارات جوال حقيقية (Web Push)**: تطبيق ويب تقدمي (PWA) مع Service Worker وWeb App Manifest ومفاتيح VAPID وخدمة إرسال في الخادم (`server/push.js`) مكتوبة بـ `node:crypto` فقط: توقيع VAPID بـ ES256 (RFC 8292) وتشفير aes128gcm (RFC 8291). اجتاز التشفير متجه الاختبار الرسمي في RFC 8291، واختبار آلي يرسل إنذارًا معتمدًا إلى خدمة Push محلية ويفك تشفيره ويتحقق من التوقيع (`test/push.test.js`).
- **إدارة أجهزة استقبال الإنذارات**: تسجيل الجوال وربطه بسفينة أو بضابط الميناء، عدة أجهزة لكل سفينة، اختبار وإزالة، ووسم الاشتراكات المنتهية (404/410) تلقائيًا.
- **مركز اختبار الإشعارات**: فحوصات (HTTPS، Service Worker، الإذن، الاشتراك، تسجيل الخادم، VAPID، خدمة الإرسال، المزامنة)، واختبارات (إشعار عادي، إشعار حرج، صوت، اهتزاز)، وسجل يفصل بين: *قبول خدمة الإشعارات* ← *عرض الإشعار على الجهاز (بإبلاغ من الجهاز نفسه)* ← *تأكيد الطاقم*.
- **مزامنة فورية** عبر Server-Sent Events (`/api/events`): تتحدث شاشة الضابط تلقائيًا عند استلام السفينة أو قبولها أو رفضها.
- **إنذار صوتي** بنغمات أصلية مولّدة (بوق ثنائي، نبضات، جرس)، يتكرر حتى التأكيد، مع كتم وتحكم في الصوت وزر «تفعيل الصوت».
- **واجهة مركز العمليات**: قائمة من ١٥ صفحة (العمليات، الاتصالات البحرية، الإدارة)، لوحة مؤشرات، خريطة مركزية مع حد المياه الإقليمية التقريبي ومواقع الانتظار، قائمة الحوادث النشطة، سجل الإشعارات والاستلام، متابعة السفن، والإعدادات.
- عند الضغط على الإشعار يفتح الجوال تفاصيل الإنذار الصحيح (`/?v=<vessel>&alert=<alert>`)، وزر «تأكيد الاستلام» في الإشعار يفتح نافذة الرد مباشرة.

### تشغيل إشعارات الجوال (اختبار B)
1. افتح الرابط المنشور (HTTPS) على الكمبيوتر وعلى الجوال.
2. على الجوال: «جسر السفينة» ← اختر سفينة عليها وسم **داخل المياه الإقليمية** ← «تفعيل إشعارات الجوال» ← «سماح».
   - iPhone: يلزم iOS 16.4 أو أحدث، وفتح الرابط في Safari ثم «إضافة إلى الشاشة الرئيسية»، وتشغيل مَرسى من الأيقونة قبل التفعيل.
   - Android: Chrome أو Samsung Internet أو Edge.
3. على الكمبيوتر: «ضابط الميناء» ← «الإنذارات المباشرة» ← «إنذار جديد» لخطر نشط مع اختيار السفينة نفسها ← المراجعة ← «اعتماد وإرسال للسفن».
4. يصل الإشعار للجوال (حتى والمتصفح في الخلفية). اضغطه ← يفتح الإنذار ← «قبول التوصية» ← تتحدث شاشة الكمبيوتر تلقائيًا، ويظهر الرد في «سجل الإشعارات والاستلام» و«سجل العمليات».

صوت إشعار النظام واهتزازه يتحكم بهما الجهاز والمتصفح (وضع الصامت/التركيز/عدم الإزعاج)، ولا يمكن ضمان تشغيل صوت مخصص والموقع مغلق.

### مفاتيح VAPID
- الأولوية: `MARSA_VAPID_PUBLIC_KEY` + `MARSA_VAPID_PRIVATE_KEY` ← أو `MARSA_VAPID_SEED` (تُشتق المفاتيح منه وتبقى ثابتة) ← أو تُشتق من سر الخادم `MARSA_INTEGRATION_KEY` ← أو تُولَّد وتُحفظ في قاعدة البيانات.
- توليد زوج مفاتيح: `node -e "console.log(require('./server/push.js').generateVapidKeys())"`.
- المفتاح الخاص لا يُرسل للواجهة أبدًا؛ الواجهة تأخذ المفتاح العام من `/api/push/config`.

### النشر على Render
- `render.yaml` يضبط `MARSA_VAPID_SEED` و`MARSA_INTEGRATION_KEY` بقيم مولّدة. إذا أُنشئت الخدمة يدويًا: أضف `MARSA_VAPID_SEED` (نص عشوائي طويل) من Environment، ثم Manual Deploy.
- **قيد الخطة المجانية**: قرص الخدمة مؤقت (`/tmp`) ويُمسح عند إعادة التشغيل أو الخمول. المفاتيح تبقى ثابتة (مشتقة من السر)، ويعيد الجوال تسجيل اشتراكه تلقائيًا عند فتح التطبيق؛ لكن البيانات التشغيلية تعود للبيانات الأولية. للإنتاج: قرص دائم (Render Disk) أو PostgreSQL.

### حسابات العرض
| الحساب | الوصول |
|---|---|
| `OFFICER` – ضابط الميناء | كل الصفحات والاعتمادات |
| `B-<vesselId>` – جسر سفينة | بيانات سفينته وأجهزتها فقط؛ لا يرى سفنًا أخرى |
المصادقة هنا **دخول عرض بلا كلمة مرور** (رموز جلسة في الخادم وصلاحيات حسب الدور). الإنتاج يتطلب مصادقة حقيقية (SSO/كلمات مرور/MFA) وإدارة مستخدمين.

### الأمان
- نقاط الاشتراك تقبل عناوين خدمات Push المعروفة فقط (Google/Mozilla/Apple/Microsoft) عبر HTTPS لمنع استخدام الخادم لطلب عناوين عشوائية.
- إيصالات Service Worker تعتمد معرفًا عشوائيًا غير قابل للتخمين لكل إشعار، والحمولة لا تحمل بيانات خاصة (اسم السفينة، رقم الإنذار، وصف مختصر).
- تحديد معدل الطلبات، التحقق من المدخلات، CSP، HSTS على Render، سجل عمليات متسلسل بـ SHA-256 يشمل تسجيل الأجهزة وإزالتها واستجابات خدمة الإشعارات وعرضها وفتحها.
- لا تُعلَّم عملية فاشلة كناجحة: «قُبل» تعني استجابة 201 من خدمة الإشعارات فقط، و«عُرض» لا تُسجل إلا بإبلاغ من الجهاز.

### القيود المعروفة (v5)
- لم يُختبر الاستلام على جوال فعلي داخل بيئة التطوير؛ الاختبار النهائي يتم على الرابط المنشور (الخطوات أعلاه).
- الخريطة SVG محلية (تكبير وسحب وطبقات ونوافذ تفاصيل) بدل Leaflet/OpenStreetMap، لأن البيئة لا تسمح بتحميل مكتبات أو بلاطات خرائط خارجية؛ حد المياه الإقليمية مرسوم تقريبيًا من خط ساحل مبسّط.
- الواجهة JavaScript بلا إطار (لا React/TypeScript) للحفاظ على النظام العامل وعدم وجود اعتماديات؛ الخادم Node.js بدل FastAPI للسبب نفسه.

## القيود والخطوات التالية
- التوقعات والقيم اختبارية، ومحرك القواعد ليس نموذج ذكاء اصطناعي مدرّبًا.
- المياه الإقليمية والأعماق تقريبية؛ تحتاج بيانات رسمية.
- الخطوة التالية: ربط المركز الوطني للأرصاد وAIS عبر المحوّلات، واعتماد صيغ التحذير مع الجهات المختصة، وصلاحيات مستخدمين حقيقية.
